# Configuration and credential boundaries

> Historical service-account/controller configuration. Do not use the `sudo` installer or paths below for the personal fleet; follow [current getting started](getting-started.md) instead.

Start with [from-zero setup](getting-started.md). [`.env.example`](../.env.example) lists the current Compose settings; `agent-config/hermes/native.env` pins the host installer. Keep actual `.env`, provider tokens, API keys, and private documents out of Git. `scripts/compose.sh config --quiet` checks the rendered Compose shape without printing interpolated secrets; `scripts/compose.sh config` **without** `--quiet` can expose them.

## Which process reads which setting?

| Boundary | Settings / location | Consequence |
| --- | --- | --- |
| Compose interpolation | Root `.env` plus exported shell variables (`docker-compose.yml`) | Shell exports override `.env`. Request DB password and file paths must exist before starting services. `scripts/compose.sh` does **not** source `.env` into host commands; its vault preflight separately reads it. |
| Host installer | `scripts/hermes-native.sh` defaults or exported `HERMES_*` paths | Does not read the root `.env`. Uses pinned `agent-config/hermes/native.env`, installs as root for the non-admin `hermes-agent` account. Changing a host path only in `.env` does not redirect the installer. |
| Fleet orchestration | `scripts/fleet.sh` exported values, then `scripts/compose.sh` | Exports defaults for authority mirror, API/key paths, policy, safety authors/orgs, and stage/handoff paths; these can override conflicting `.env` values in Compose. Empty `PR_SAFETY_ALLOWED_ORGS`/authors are replaced by its defaults. |
| Host Hermes credentials | `/Users/hermes-agent/.hermes/.env`, installed profiles, service-user GitHub configuration/deploy keys | Model and GitHub effects run under the service account, not in the Compose controller. `configure-hermes-api.py` reads `GH_TOKEN` from the service-account `.env` at install time; its copy remains available to legacy producers. Default review cron uses its separate discovery token and profile key files. |

Use the default host paths for a first installation. If overriding them, supply consistent host variables to each command; for privileged calls pass explicit `sudo env NAME=value ...` rather than assuming `sudo` preserves shell exports. Check generated paths before starting Compose. Never pass secret values on a command line. The producer authority mirror (`HERMES_DOCKER_AUTHORITY_FILE`) is generated by `fleet.sh up` from `HERMES_AUTHORITY_SOURCE_FILE`; an `.env` edit alone does not change what the host script reads.

## Required substrate and UI settings

| Group | Values | Operator check |
| --- | --- | --- |
| Host paths | `CODE_ROOT`, `SWARMVAULT_VAULT` | Both must be absolute; vault must be outside code root. Coderag mounts code read-only, vault watcher has vault write access. Replace user-specific template paths. |
| Request DB | `REQUESTS_DB_PASSWORD`, optionally `REQUESTS_DB_USER`/`NAME`/`PORT` | Postgres stores requests, `hermes_runs`, and decisions. `REQUESTS_DB_PORT` publishes to the host without a loopback-only binding in Compose; restrict network access. Changing `.env` password after first DB initialization does **not** rotate its existing password. |
| Hindsight | `HINDSIGHT_DB_PASSWORD`, keyed `HINDSIGHT_API_LLM_PROVIDER`/`HINDSIGHT_API_LLM_API_KEY` | Hindsight retain uses a paid model; a keyless interactive login will not work headless. Hindsight API is loopback-bound on host port 8888. Never change the pinned PG18 volume mount/tag without migration. |
| Fleet Controller | `FLEET_CONTROLLER_USERNAME`, four `FLEET_CONTROLLER_*_FILE` secret/cert paths; optional `STATUS_PORT` | Generate TLS with `scripts/generate-ui-tls.sh`; set paths to its output (session secret is generated separately). Key and session secret: regular, non-symlink, owner/root-owned, mode `0600`, owner-only parent. Leaf/CA must pass `validate-fleet-controller-secrets.py`. UI proxy binds localhost:8080 by default. |
| Review cron | `GITHUB_DISCOVERY_TOKEN_FILE`, `HERMES_REVIEW_API_KEY_FILE`, `PR_REVIEW_CRON_SCHEDULE` | Default review requires two nonempty owner-only files: a repository discovery token and only the `pr-review-v1` API key from the installed bundle. Cron runs every five minutes unless its schedule is changed. |
| Direct maintenance preview | `GITHUB_DISCOVERY_TOKEN_FILE`, `HERMES_MAINTAIN_API_KEY_FILE`, optional `PR_MAINTAIN_CRON_SCHEDULE` | `direct-maintain` profile only; stop the default maintenance producer before enabling it. The discovery token must identify the **same GitHub login** as the installed maintenance profile to exclude its own replies. The direct path has no controller round cap. |
| Producer scope | `/usr/local/etc/ai-pr-automation/authority.yaml`, `HERMES_AUTHORITY_SOURCE_FILE`, `HERMES_DOCKER_AUTHORITY_FILE` | Authority is *scope of attention*, not security. Replace wildcard entries with explicit repositories for a narrow pilot; use `scripts/hermes-authority.py --file <path> --check owner/repo`. `PR_PRODUCER_REPOSITORIES`/`ORGS` are Fleet Controller's **manual PR-injection allowlist**. Both empty with `PR_PRODUCER_ALLOW_ALL_REPOS=false` deny manual PR injection by default; adding a repo/org lets a UI action enqueue paid/effect-capable work. They do not configure automatic producer discovery or replace its authority checks. Keep scopes aligned; manual review injection is not a reliable failed-review retry (see [operations](operations.md#controller-recovery)). |

## Secret files and host mounts

| File/path | Created or used by | Boundary |
| --- | --- | --- |
| `HERMES_API_KEYS_FILE`, `GITHUB_READ_TOKEN_FILE` | Native installer (`configure-hermes-api.py`) | Must share one operator-owned, owner-only (`0700`) Docker-readable parent directory outside the repository; generated files are `0600`. API bundle is mounted into **controller**; copied GitHub token into **producers**. Check the token's actual GitHub scopes, not the filename. |
| `HERMES_KANBAN_BRIDGE_KEY_FILE`, `HERMES_KANBAN_BRIDGE_CONTROLLER_KEY_FILE` | Native installer creates service-owned HMAC key; `fleet.sh up` copies bytes to operator-owned file | Controller receives only copy as a Compose secret. Do not rotate while attempts submit; drain/reconcile first. |
| `DOC_WRITER_STAGE_HOST`, `DOC_WRITER_INBOX_HOST` | Host document stage; Compose status preview is read-only and controller has publication access | The exact-byte human approval gate precedes publication. Point inbox at an approved writable host destination, not an example user path. |
| `PR_SAFETY_SNAPSHOT_ROOT`, `HANDOFF_ROOT`, `PR_SAFETY_POLICY_PATH`/`VERSION`/`DIGEST` | Merged-PR snapshots, immutable handoffs, pinned assessment policy | Snapshots mount read-only to controller; handoff output is sensitive. Validate policy digest before enabling PR-safety. |
| `MEMORY_SOURCE_HOST`, `MEMORY_CURATOR_STATE_HOST` | Compose controller memory curation | Source mounts read-only, but proposed memories can leave the host for configured team/org destinations. Do not point at private docs without explicit data-boundary approval. |

The host service account's provider OAuth, repo deploy keys, browser state, and service home are **not** controller mounts. `hermes-controller` calls `http://host.docker.internal:8642` with profile-scoped Runs API keys. Its Kanban bridge uses a separate HMAC key at `http://host.docker.internal:8766`. These plaintext host-loopback/Docker Desktop links assume one trusted macOS host; do not transplant the design to a multi-host network without a new transport/security design. See [architecture](architecture.md).

## Workflows and switches

- The commented `PR_REVIEW_DISCOVER_ALL_OWNERS` and `PR_MAINTAIN_DISCOVER_ALL_OWNERS` examples in `.env.example` are **not wired into Compose or host launchd**. Default review/maintain search remains `--assignee @me` / `--author @me`; adding owner/* authority alone does not activate owner-wide search. Do not rely on those variables for startup scope.
- Review now uses the Compose cron and Hermes Runs API by default. The old `fleet.sh review-kanban-up`/`review-postgres-up` switches have been removed. `PR_MAINTAIN_QUEUE_ENGINE=postgres` and `MEMORY_CURATE_QUEUE_ENGINE=postgres` remain default for those kinds; `maintain-kanban-up` and `memory-cron-up` still change their live producers. Follow [operations](operations.md#queue-engine-changes).
- `PR_SAFETY_QUEUE_ENGINE=postgres` and `PR_SAFETY_ANALYSIS_ENGINE=single` preserve current one-run PR-safety path. Kanban council admission is an explicit, separate policy/cost decision; the bridge may still run under `single` to recover an older attempt.
- `PR_SAFETY_MERGED_PR_AUTHORS` and `PR_SAFETY_ALLOWED_ORGS` are additional PR-safety discovery scope. A matched author in an allowed organization can be admitted **even if the repo is absent from authority.yaml** (the producer tests repo grant **or** allowed org). `fleet.sh` defaults to `roktfleet,brucerokt` and `ROKT` when shell variables are unset/empty. Do not infer a one-repo safety pilot from a one-repo authority file.
- Enabling `swe-implement` or submitting a document through the UI can invoke a paid profile and generate a draft PR or approved document. The default `fleet.sh up` also starts PR and memory discovery; it is not a review-only opt-in. See [architecture](architecture.md#workflows-and-effects) and [operations](operations.md).
