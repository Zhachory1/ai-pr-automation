# Implementation plan: multi-profile PR review council

- PRD: [PRD-pr-review-council.md](PRD-pr-review-council.md); design: [DD-pr-review-council.md](DD-pr-review-council.md); issue [#341](https://github.com/Zhachory1/ai-pr-automation/issues/341).
- Operator requested direct implementation, **no shadow pilot**. This issue's direct-Kanban plan supersedes the old roadmap's M3 shadow gate for PR review only; fake-effect validation, one-writer safety, and bounded rollout remain. Existing `pr-review-v1`/`pr-maintain-v1` behavior stays intact until the cutover gate passes.

| Slice | Depends on | Acceptance / focused validation | Stop condition |
|---|---|---|---|
| 0. Scope and installed drift | Operator direction | Define existing-producer eligibility, owner-fenced `(repo, PR, head)`, exact marker, concrete 3+optional-security profile IDs and deterministic path triggers. Treat 8-minute/75k-token/two-active limits as implementation ceilings. Repo SOUL/skill use Kanban; installed SOUL/skill still use old Runs API wording. Keep normal task model override Sonnet 4.6; do not overwrite installed default config without a decision. | Unclear old/new owner or snapshot access scope. Operator approved owner-only local content until effect verification/reconciliation, with immediate content removal afterward; no seven-day retention. |
| 1. Read-only council | 0 | First find an existing local checkout and pin Git base/head objects; no clone, branch switch, or copied diff. Keep bounded owner-only PR context; every eligible unbound head creates the three named profiles, optional security by changed-path trigger, and exactly one synthesis without approval-brief card. Exact 3/4-role contracts, restricted profile/toolsets, same digest, typed findings, dissent, missing/timeout fail-closed; fake Kanban + safe tool-surface tests. No GitHub writer. | Specialist can access GitHub writes, pinned local commit missing, replay changes graph, budget exceeded. |
| 2. Single writer | 1 | Host-only one-review publisher with final open/head/base check, exact existing marker, paginated prior feedback/marker lookup, `post_started → verified|reconcile`, head-pinned GitHub event, nits allowed under `APPROVE`; fake GitHub timeout/accepted-then-crash/replay/self-review/wrong-head tests. Specialists cannot post. | Any duplicate/wrong-head/unverifiable review can settle as posted. |
| 3. Versioned admission | 1, 2 | Producer/ingress atomically select council for every eligible future unbound head using the existing immutable `request.json` as the shared one-writer fence and the existing `pr-review` board/response; preserve old task bindings. Test concurrent legacy/council admission, partial setup/replay, old-task behavior, head rollover, and 401/protocol failures; current PR maintenance untouched. | Old and new paths can both post for one head or existing tasks are reinterpreted. |
| 4. Code review and activation | 3 | Independent code review of spec and diff, focused required checks, no private fixtures. Confirm pinned local Git read authority and installed profile bytes, pause only review admission, inspect active/uncertain old work, perform compatible client/ingress rollout and observe first cycles under fixed limits. No auto merge. | Review blocker, unsafe in-flight migration, missing permissions, unsupported snapshot tools, or wrong effect. |

Current repo `evals/` cases score recorded effect contracts, not real finding precision/recall; no threshold claim or new scoring service is part of this issue. Track verified material findings and false approvals from production only after an accountable human adjudicates them. Optional security triggers are deterministic and immutable per head; dynamic model-picked rosters are out of scope. Autopraxis supplies review principles, not its different marker or delivery contract.
