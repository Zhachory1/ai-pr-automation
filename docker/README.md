# Local fleet containers

`docker-compose.yml` runs Hindsight and its Postgres DB, Coderag, nginx, and direct PR review/maintenance cron producers. Hermes itself runs as the current user's `~/.hermes` gateway. Review discovers assigned PRs across accessible repositories and sends exact-head cards to the local Hermes dashboard API at `host.docker.internal:9119`; maintenance still sends signed requests to the host Kanban ingress at `host.docker.internal:8767`. There is no fleet request queue, controller, or status server in the default runtime.

From the repo root, configure `.env` (or set `COMPOSE_ENV_FILES` to the operator env file). `scripts/fleet.sh support-up` starts only Hindsight, Coderag, and the proxy; it does not start cron producers or modify the personal Hermes gateway. After starting the dashboard and maintenance host ingress and placing a read-only GitHub discovery token and maintenance ingress key in owner-only paths listed in `.env.example`, set `PR_REVIEW_WORK_ROOT` to the host's absolute review workspace directory. `scripts/fleet.sh up` starts maintenance only. Review is gated by the `pr-review-mvp` profile and must remain stopped until the [replacement design](../docs/DD-pr-review-github-files.md) and old-card archival cutover are complete. Preserve the separate legacy review ingress key outside Compose until old council-bound heads settle. This is live PR discovery and can trigger model and GitHub effects; do not use it as a health check.

Use `scripts/fleet.sh status` and `scripts/fleet.sh logs` for inspection. `scripts/fleet.sh down` stops Compose services, **not** the personal Hermes gateway; it does not delete volumes. Never use `docker compose down -v`. Historical request data is archived offline, including unresolved `reconcile` records. Do not replay them without checking external effects.

The Compose nginx proxy publishes only loopback ports: HTTP on `127.0.0.1:80` for port-free `*.localhost` aliases, plus the existing HTTPS `127.0.0.1:8080`. `hermes.localhost` reaches the authenticated API; <https://fleet.localhost:8080/> serves the existing local Hermes Kanban dashboard, with `dashboard.localhost` redirecting there. `memory.localhost` reaches Hindsight UI, `memory-api.localhost` Hindsight API, and `code.localhost` Coderag. Unknown port-80 hosts are rejected; retired `localhost/signal/` returns 410. Signal uses the current user's `ai.hermes.signal` LaunchAgent and `~/.local/share/signal-cli`. The unused Docker Signal service starts only if explicitly targeted or the `legacy-signal` profile is enabled; its `signal_state` volume is retained for rollback.

Hindsight's `hindsight_pgdata` must remain on `pgvector/pgvector:pg18` at `/var/lib/postgresql/18/docker`. Changing either the major version or mount path without a migration can silently initialize an empty database. `hindsight-bank-init` sets the shared bank's read-only MCP tools when the full runtime starts; `support-up` does not rerun it. The host Hermes profiles use the recall-only shim on `127.0.0.1:8888` and Coderag MCP on `127.0.0.1:9750`. A live recall may use a model; tool discovery alone does not.
