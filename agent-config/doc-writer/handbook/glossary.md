# Glossary of Rokt and Engineering Terms

> **Source**: go/dev-handbook
> **Related files**: [business-context.md](business-context.md) (metrics definitions), [welcome.md](welcome.md) (culture and principles)

| Term | Definition | Primary Level |
| :--- | :--- | :--- |
| 2-Up People Leader | The People Leader of your People Leader, often required for key approvals. | — |
| ADR (Architecture Decision Record) | A document recording interface and architectural decisions in-repo with links to contracts and runbooks. | — |
| Aftersell | Post-purchase upsell product, primarily for SMB partners on Shopify. | — |
| AOV (Average Order Value) | The average value of orders generated from conversions. | Metric |
| API (Application Programming Interface) | Application Programming Interface. | — |
| APT (Activity Per Transaction) | Ad revenue generated per partner transaction—primary relevancy metric. | Metric |
| AppGate SDP | Software Defined Perimeter—VPN solution for accessing internal network and systems. | — |
| BNPL (Buy Now, Pay Later) | A type of payment option that allows consumers to purchase goods or services and pay for them in installments. | — |
| Bounded Context (BC) | A logical boundary within which a specific domain model is defined, consistent, and applies. A core concept in Domain-Driven Design (DDD). | Global Architecture |
| Bug | A verifiable deviation from expected or specified system behavior. | Technical / Local |
| Builder DNA | A mindset defining how Rokt'stars operate—focused on ownership, collaboration, and rapid execution. | — |
| Buildkite | The underlying CI/CD job runner for Rokt deployments. DeployKit is the abstraction layer builders interact with; Buildkite is where you monitor deployment status and approve blocking steps. | — |
| Component | A single, isolated, and highly focused microservice, library, or data pipeline within a larger System. It solves a singular, tactical problem. | System Architecture / Local Design |
| CoPI (Customer Outcome Performance Index) | Measures customer relevancy—how relevant the experience is to the user. Also defined as Conversion per Offer Impression: percent of users who reached a target conversion event after seeing a Rokt Ad creative (conversions/impressions x 100%). | Metric |
| Cortex | Service catalog tool for managing service metadata, ownership, and scorecards. | — |
| CPA (Cost Per Acquisition) | Advertiser metric: cost to acquire a customer. Total cost spent to acquire a new customer, divided by number of new customers acquired. Central metric for campaign performance and optimization. | Metric |
| CPA Campaigns | Campaign objective to maximize conversions (sign-ups, trials, purchases) at or below a target CPA. Smart bidding option is "Maximize conversions at a CPA target" when eligibility criteria are met. | — |
| CPC (Cost Per Click) | The average cost for each click on an ad. | Metric |
| CPR (Cost Per Referral) | The average cost for each customer referral (positive opt-in). | Metric |
| CPT (Cost Per Transaction) | The average cost per transaction (or conversion event) generated by a campaign. | Metric |
| Creative | The content that represents an advertiser's offer to a customer. | — |
| CVR (Conversion Rate) | The percent of users who reached a target conversion event after engaging with a campaign creative (conversions/referrals x 100%). | Metric |
| DeployKit | Rokt's standard CI/CD abstraction layer that sits in front of Buildkite. Builders interact with DeployKit configuration; monitor and approve deployments in Buildkite. | — |
| Derived Data | Data derived from customer interactions with the Rokt Platform. | — |
| Design Doc (DD) | A deep-dive artifact detailing the System architecture, Component design, data models, APIs, trade-offs, and implementation plan for a Feature or Project. | System / Component Design |
| DRI (Directly Responsible Individual) | Individual accountable for the success or failure of a specific project. | — |
| EMQ (Event Matching Quality) | Score measuring closed-loop integration quality for advertisers. A score (1–10) indicating how well the customer data attached to conversion events matches real customer profiles in Rokt's system. Higher EMQ = better attribution and optimization. | Metric |
| End Customer | A customer of, or visitor to, the Partner's digital property. | — |
| Engagement Campaigns | Campaigns using the Rokt Platform for surveys, offers, loyalty programs, etc. | — |
| Engagement Rate | Percent of customers who engage with an ad creative or campaign (referrals/impressions x 100%). | Metric |
| ExCo (Executive Committee) | Senior leadership team responsible for strategic decisions. | — |
| Experiment | A time-boxed, measurable test of a hypothesis to determine its impact (e.g., A/B Test, Multi-Armed Bandit). | Measurement / Science |
| Feature | A distinct, measurable unit of end-user or system functionality that provides business value. It is what an engineer delivers and a Product Manager defines. | Product / System |
| FPHP (Flexible Public Holiday Program) | Allows Rokt'stars to swap designated holidays for ones meaningful to them. | — |
| GKO (Global Kick Off) | An annual company event to align all Rokt'stars on goals and strategy. | — |
| GoLinks | Shared bookmark service using go/shortcut format (e.g., go/datadog). | — |
| High 5 Days | Bonus PTO awarded to Rokt'stars who use most of their annual leave. | — |
| IC Specialist | Senior ICs with flexible office requirements, not eligible for people leadership. | — |
| Impressions (I/M) | Number of times a campaign creative was rendered in the placement. "M" denotes a thousand impressions. | Metric |
| Istio | Service mesh for Kubernetes, managing traffic between services. | — |
| K8s (Kubernetes) | Container orchestration platform; Rokt uses AWS EKS. | — |
| Lightning Rod | A one-page memo used for proposing ideas and achieving cross-functional alignment. | — |
| LTV:CAC | Lifetime Value to Customer Acquisition Cost ratio—key advertiser efficiency metric. | Metric |
| mParticle CDP | Customer data platform for identity resolution and audience management. | — |
| OKRs (Objectives and Key Results) | A goal-setting method using qualitative objectives and measurable key results. | — |
| One Platform (OP2) | Single page application used by Partners, Providers, Advertisers, and Account Managers. | — |
| Post-Mortem / Incident Review | A formal, blameless review of a significant incident (outage, degradation, or major failure) focusing on what happened, why it happened, the impact (SLO breach), and concrete action items to prevent recurrence. | Reliability / Process |
| PRFAQ (Press Release and FAQ) | A document combining a mock press release and FAQs to define a new initiative's value. | — |
| Product | The customer-facing, monetizable offering. A collection of features and services that solves a specific business problem for a client. | Business / Global Architecture |
| Project | A time-boxed, cross-functional, and often cross-system effort required to deliver one or more related Features. It typically involves architectural, dependency, or business changes. | Effort / Roadmap Management |
| PTO (Paid Time Off) | Paid leave. Referred to as "Annual Leave" in some markets. | — |
| RBC (Revenue Based Campaigns) | The objective is to maximize revenue generated from those conversions relative to ad spend. Primary KPI/optimization target is ROAS, using integrated transaction value and currency in conversion events. Smart bidding strategy is "Maximize revenue at a ROAS target". | — |
| Referral | An End Customer interaction with the Rokt Placement indicating affirmative intent (e.g., app download, sign-up). Also defined as: Number of customer opt-ins or clicks on a campaign (positive engagement) (R/C). | — |
| Regression | A change that causes a previously working feature or system behavior to stop working correctly, or to perform measurably worse (e.g., increased latency, lower model accuracy). | Quality / Execution |
| REX (Rokt'star Extender) | ICs in non-office locations that may be engaged through third parties. | — |
| ROAS (Return on Ad Spend) | Advertiser metric: revenue generated relative to ad spend. Revenue generated by an ad campaign divided by the total spend on that campaign. Shows efficiency of marketing investment. | Metric |
| Roadmap Document | A visual, time-based plan that sequences the specific Projects, Epics, and Features the team commits to deliver over a specific time horizon (typically 6-12 months). | Execution/Timeline Management |
| Rokt Ads | Advertiser-facing performance marketing platform. | — |
| Rokt Brain | AI/ML decisioning engine that selects the most relevant experience. | — |
| Rokt Catalog | Product catalog ingestion and AI-powered merchandising platform. | — |
| Rokt Pay+ | Payments page monetization product. | — |
| Rokt Placement | The technology that Rokt provides to interact with End Customers and integrate data from the Partner Website to the Rokt Platform. | — |
| Rokt Thanks | Post-purchase partner-facing experience product. | — |
| RoktGPT | Internal AI assistant for Rokt platform knowledge and documentation. | — |
| RON (Run-of-Network) | Ads are served across an entire ad network rather than targeting specific sites or placements within that network. The goal is to maximize reach and impressions, usually at a lower cost compared to targeted campaigns. | — |
| RTA (Required Technology Allowance) | An allowance for purchasing and maintaining compliant technology equipment. | — |
| RTTI (Rokt Time to Interactive) | Time for Rokt widget to become interactive on a page. | Metric |
| Sabbatical | Paid leave available to long-tenured employees for personal pursuits. | — |
| Service Level Objective (SLO) | A target value for a service's reliability, measured over a defined period (e.g., Latency, Throughput, Error Rate). | Reliability / System Architecture |
| Service Tier | Classification of service criticality (T0-T3) defining availability and recovery requirements. | — |
| Signals/Model Inputs | To differentiate from Features (defined as product functionalities), we define the inputs to Machine Learning model training and predictions as Signals or Model Inputs. | — |
| SLIs, SLOs, SLAs | Service Level {Indicator, Objective, Agreement}. Respectively, they are our quantitative measure of some aspect of the service, the target value we would like to achieve for that indicator, and the contractual required minimum for that indicator. | — |
| SOV (Share of Voice) | The percentage of placements where an advertiser's brand appears, relative to total placements audited for a competitor/platform. Used to benchmark visibility. | Metric |
| STO (Single Threaded Owner) | A leader responsible for an entire mission, managing cross-functional teams with a clear northstar metric. | — |
| Strategy Document | Defines the high-level approach, measurable goals, and major initiatives (Projects) required to move closer to the Vision (typically 6-18 months). | Product / Engineering Leadership |
| System | A large, distinct, independently deployable, and logically cohesive set of services. It represents a major component in the Service-Oriented Architecture (SOA), often aligning with a bounded context in Domain-Driven Design (DDD). | Global Architecture |
| T200 | Top 200 strategic ecommerce accounts—Rokt's most important partners. | — |
| Task | A non-feature-related, small, self-contained piece of work, often related to maintenance, debt, or a step within a larger Project. | Execution / Local |
| Technical Debt (TD) | The implied cost of additional rework caused by choosing an easy (limited) solution now instead of a better, longer approach. Deferred maintenance. | System Architecture / Execution |
| Transaction Moment™ | The critical moment in the customer journey where Rokt delivers relevant experiences. | — |
| Trino/DBT | Data warehouse query and transformation tools for accessing Rokt's data. | — |
| Upcart | Cart upsell product, primarily for SMB partners on Shopify. | — |
| Upsell Campaign | Campaigns where End Customers purchase products or services via the Rokt Placement. | — |
| Vision Document | A high-level, stable artifact defining the long-term purpose and ideal future state of a Product, System, or the company itself (2-5+ years out). | Executive / Global Strategy |
| VPT (Value Per Transaction) | Total value generated per transaction for partners. | Metric |
| VRT (Visual Regression Testing) | Internal tool for ensuring frontend changes don't unintentionally impact UI components. | — |
| YER (Yield Efficiency Ratio) | APT divided by CoPI—measures how efficiently relevancy converts to revenue. | Metric |
